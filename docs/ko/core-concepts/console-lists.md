# 콘솔 목록

콘솔 목록이 무엇을 그릴지 정하는 방식을 설명합니다. 좁은 창에서 남는 컬럼, 행을 표로 그릴지 카드로 그릴지, 필터를 만들고 주소에 보관하는 방법, 행 동작을 그리는 방법을 다룹니다.

## 목록 컬럼

목록은 창에 들어가는 만큼 컬럼을 그립니다. 생성된 컬럼 집합에서 앞의 네 컬럼에는 폭 조건이 없고, 그 뒤의 컬럼에는 해당 컬럼까지의 폭이 조건으로 붙습니다. 그래서 창이 좁아지면 필드 순서의 끝에서부터 컬럼이 빠집니다. 화면이 앞의 네 컬럼 뒤에 직접 추가한 컬럼(파생 표시)도 순서상 위치에 따라 같은 종류의 단계를 받습니다(`ladderColumns`, `RecordList`가 적용). 그래서 항상 그리는 집합에 들어가 태블릿 폭에서 표를 카드로 바꾸는 대신 다른 컬럼과 함께 빠집니다. 다음 컬럼은 빠지지 않습니다. 빠지면 화면을 읽을 수 없거나 내용이 사실과 달라지기 때문입니다.

- 행의 이름을 표시하는 맨 앞 컬럼
- 행을 정렬한 컬럼. 목록의 현재 정렬 컬럼이며, 사용자가 다른 컬럼을 고르기 전까지는 기본 정렬 컬럼입니다. 그리지 않는 컬럼으로 정렬한 목록은 자신의 순서를 확인할 수 없습니다.
- 화면이 유지하도록 지정한 컬럼(contract 필드나 컬럼의 `keep: true`). 이 컬럼이 없으면 다른 컬럼이 잘못 읽힙니다. "동의함" 옆의 동의 철회가 그런 예입니다. 유지하는 컬럼은 모두 가장 좁은 표에 더해지므로, 유지 집합이 가장 좁은 창보다 커진 목록은 카드로 바뀝니다.
- 행 동작 컬럼. 컬럼 집합이 아니라 표에 속합니다.

유지하는 컬럼은 폭 단계에서 빠지고, 그 앞의 모든 단계는 유지 컬럼이 항상 차지하는 폭만큼 커집니다(`console-core/src/entity/column-priority.ts`의 `keepColumnsDrawn`, `RecordList`가 적용). 그래서 나머지 컬럼은 계속 끝에서부터 빠지고 표는 창보다 커지지 않습니다. 로그형 목록의 시각 컬럼은 기본 정렬 컬럼이므로 모든 폭에서 화면에 남습니다. 정렬 필드가 필드 배열에 컬럼으로 없는 화면은 사용자가 볼 수 없는 값으로 정렬됩니다. 이때는 필드 배열에 컬럼을 추가합니다. 컬럼의 폭은 contract 종류에서 정해집니다(enum 컬럼은 옵션 레이블과 무관하게 120px). 가장 긴 레이블이 이보다 넓은 컬럼은 목록과 보드 프레임에 자체 `width`를 선언해야 하며, 그렇지 않으면 레이블이 말줄임표로 잘립니다.

컬럼 메뉴에는 선언한 모든 컬럼이 나옵니다. 폭 때문에 빠진 컬럼은 선택 해제 상태로 나오고, 켜면 폭과 무관하게 그리므로 표가 가로로 스크롤됩니다. 끄면 다시 폭에 따라 표시 여부가 정해집니다.

`packages/console-core/scripts/list-columns-rendered.mjs`는 그려진 목록을 이 규칙과 대조합니다. `probe`는 그려진 헤더와 정렬 표시를, `probeMenu`는 열린 컬럼 메뉴를 읽습니다. `compare`는 정렬 컬럼과 맨 앞 컬럼이 그려졌는지, 메뉴에 모든 컬럼이 나오고 그려진 컬럼이 선택 상태인지, 나머지가 끝에서부터 빠지는지 확인합니다. 제품의 실행기는 각 목록을 페이지 폭별로 열고 목록의 정렬 컬럼을 전달합니다. 빠진 컬럼에는 정렬 표시가 없기 때문입니다. `--selftest`로 자체 검증합니다(`pnpm test`).

값이 다른 대상을 여는 `text` 필드에는 `linkOf`를 지정합니다. `linkOf`는 행에서 주소를 만드는 함수입니다. 지정하면 셀, 카드, 상세가 값을 그 주소의 링크로 그립니다(해당 버전의 게시 본문을 여는 문서 버전이 그 예입니다). 주소의 출처가 다르면 새 탭으로 열고, 주소를 반환하지 않는 행은 일반 텍스트로 그립니다. 주소는 화면이 정하고 kit은 그리기만 합니다.

셀, 카드, 수치 타일의 날짜와 금액은 같은 contract 종류로 그리므로 셀과 그 위 타일의 표기가 같습니다. `money` 필드는 저장된 스케일만큼 소수 자릿수를 유지하고, 일수는 `daysAgoText`로 표기합니다. `daysAgoText`는 복수형을 카탈로그 문자열이 아니라 사용자의 언어에서 가져옵니다.

화면이 직접 잘라야 했던 텍스트는 contract 종류 `prose`, `language`, `boolean`으로 처리합니다. `prose`는 사람이 쓴 글입니다. 목록 셀이나 카드는 앞의 `proseLength`자(기본 200)를 단어 단위로 자르고 말줄임표를 붙이며, 상세는 전체 글을 패널 폭으로 그립니다. `language`는 저장된 언어 코드를 사용자의 언어로 된 언어 이름으로 표시하고, 언어 태그가 아닌 코드는 받은 그대로 그립니다. `markWhenTrue`가 있는 `boolean`은 값이 참인 행에 필드 레이블을 이름으로 한 배지를 그리고 나머지 행에는 아무것도 그리지 않으며, 배지가 없는 카드에 빈 칸을 남기지 않습니다. 상세에서는 예 또는 아니요를 그대로 표시합니다.

## 목록 표시 방식

목록 화면은 표 또는 카드로 설계하며, `RecordList`는 같은 컬럼 선언으로 둘 다 그립니다. `presentation`은 `"table"`(기본값. 컬럼에 필요한 폭보다 좁아지면 표가 카드로 바뀜) 또는 `"cards"`입니다. `"cards"`는 모든 폭에서 모든 행을 카드로 그립니다. 이 카드는 좁은 표가 바뀌는 카드와 같습니다. `record-card.ts`가 제목 컬럼, 배지 행, 레이블이 붙은 줄, 제목 옆의 행 동작을 배치하므로, 화면은 카드용 컬럼 집합을 따로 선언하지 않습니다. `cardTitle`에는 카드의 제목이 되는 컬럼(그 `key`)을 지정하며, 없으면 첫 컬럼입니다. 나머지 컬럼은 순서를 유지합니다. 없는 컬럼을 `cardTitle`에 지정하면 예외가 발생합니다.

카드는 맞춤 그리드에 배치됩니다. `--card-min-width` 레이아웃 토큰보다 좁지 않은 카드가 들어가는 만큼 열을 만들고 각 열은 행을 균등하게 나눕니다. 그래서 목록 옆에 상세 패널이 열리면 카드가 다시 배치되고, 카드 하나보다 좁은 창에서는 한 열로 그립니다. 카드의 레이블 줄은 그리드 하나로 배치합니다. 레이블 열의 폭은 가장 긴 레이블에 맞추되 `--console-card-label-max` 토큰을 넘지 않고, 그보다 긴 레이블만 줄바꿈합니다. 값은 카드 아래로 한 열에 놓입니다. 어떤 카드든 값이 있는 줄은 페이지의 모든 카드에 그리고 값이 빈 카드에는 붙임표(-)를 표시하며, 값이 있는 카드가 하나도 없으면 그리지 않습니다. 컬럼에 `cardKeep: false`를 지정하면 값이 있는 카드에만 그리고, `cardKeep: true`를 지정하면 값의 유무와 관계없이 모든 카드에 그리므로 데이터와 무관하게 카드 높이가 같습니다. 표의 정렬 가능한 헤더는 카드에 없습니다. 카드 목록은 기본 정렬 순서로 읽습니다.

모든 카드 목록에 같은 기준을 적용합니다. 카드로 그리는 목록(`presentation="cards"`)은 항상 표로 전환하는 스위치를 제공합니다. 화면이 무엇을 전달하든 `viewToggle`은 참이고, 사용자의 선택은 목록별로 기억합니다. 표 목록은 설계 항목에서 행을 단위로도 읽는다고 정한 경우에만 카드 전환 스위치를 제공하며, 그 사유는 `list.toggleReason`에 적습니다. 열 수는 `--card-min-width` 레이아웃 토큰(`console-card-min`, 20rem)과 목록 자신의 폭만으로 정해집니다. 같은 목록 폭에서는 모든 카드 목록에서 카드의 열 폭이 같으며, 화면은 카드 폭, 최대 폭, 열 수를 지정하지 않습니다. 카드 안의 레이블 열도 같은 규칙(가장 긴 레이블, `--console-card-label-max` 토큰까지)을 따르며 모든 카드 목록에서 같습니다. 렌더링 영역 프로브가 이를 측정합니다. `scripts/regions-rendered.mjs`의 `compareCardGrid`는 각 카드를 열 폭과 첫 카드의 폭에, 첫 카드를 목록의 왼쪽 안쪽 여백에, 이웃한 카드를 그리드 간격에 맞춰 판정합니다.

`viewToggle`은 사용자에게 표 보기와 카드 보기를 제공합니다. 위치는 필터 바이고, 필터가 없는 목록에서는 목록 자체의 툴바입니다(`CrudList.ViewToggle`). `presentation`은 목록을 처음 열 때의 보기입니다. 브라우저는 사용자의 마지막 선택을 `console.listView.<viewKey>`에 저장하고 다음 방문 때 그 보기로 엽니다. `viewKey`는 제품의 목록 가운데 해당 목록을 가리키는 이름이며, 화면이 지정하지 않으면 목록 컬럼 키의 해시입니다. 스위치가 없는 목록은 저장된 보기를 읽지 않으므로 `presentation`이 유일한 보기입니다. 이 결정은 화면의 설계 항목(`list.presentation`, `list.viewToggle`, `list.cardTitle`)에서 내리고, 스캐폴드에 `--list-presentation`, `--card-title`, 그리고 표 목록에 한해 `--view-toggle`로 전달합니다. 카드 목록은 플래그 없이 스위치와 키를 갖고, CLI는 카드 목록에 이 플래그를 주면 거부합니다. mockup 패키지의 `screen-design` 검사는 `<RecordList>`가 설계와 다른 값을 선언한 목록 파일이나 보드 프레임을 거부합니다.

## 목록 필터

생성기는 엔티티의 검색 가능한 필드를 목록 필터(`ContractFilter`)로 만듭니다. enum은 `choice`, boolean은 `toggle`, 시각이나 날짜는 `dateRange`, 수치는 `number`(`money` 필드는 통화와 스케일도 포함), 다른 레코드의 키는 그 레코드의 이름으로 거르는 `reference`가 됩니다. 텍스트 필드는 키워드 검색에 맡깁니다. 필드마다 자유 입력 칸을 두는 것이 화면의 질문에 맞는 경우는 드물기 때문입니다. 텍스트 필드로 조회해야 하는 화면(제공자별, 플랜 코드별)은 설계에 그 필드를 적고 `--text-filter <field,field>`로 스캐폴드합니다. 그러면 목록이 `{ kind: "text", field, operators }`를 선언합니다. `operators`는 엔드포인트가 그 필드에 허용하는 연산자이며 첫 번째가 기본값입니다. 서버가 전체 일치로만 조회하는 필드는 `["equals"]`이고, 이때 필터 바는 서버가 빈 페이지로 응답할 `contains`를 제공하지 않습니다. 이 플래그는 생성 출처에 기록하므로 다시 생성해도 같은 필터가 나오며, 엔티티의 검색 가능한 텍스트 필드가 아닌 이름을 주면 실행이 중단됩니다.

## 주소에 담는 목록 필터

생성된 목록은 확정된 필터를 페이지 주소에 보관합니다. 그래서 링크로 이미 필터가 적용된 목록을 열 수 있고("실패한 작업 4건" 타일이 그 4건을 여는 경우), 새로 고쳐도 필터가 유지되며, 뒤로 가기를 한 번 누르면 사용자가 시도한 필터를 하나씩 거치지 않고 화면을 벗어납니다. 전송할 때 필터는 키마다 대괄호 매개변수 하나입니다(`?filters[status.in]=FAILED`).

화면이 주소를 전달하는 방법. `use<Entity>List(params?, address?)`는 주소를 `{ value, onChange }`로 받습니다. 생성된 `crud-page.tsx`는 자신의 props만으로 이를 만듭니다.

```tsx
const list = useJobList(blocks.listParams, {
  value: search.filters,
  onChange: (next) => onNavigate({ ...search, filters: next }, { replace: true }),
});
```

`onNavigate`는 두 번째 인자로 라우터의 이동 옵션을 받고(`PageBlocksContext`, 페이지의 props, 라우트가 모두 이를 전달), 라우트는 `replace: options?.replace`를 `navigate`에 넘깁니다. 그래서 필터 변경은 히스토리 항목을 교체하고, 레코드 열기는 항목을 추가합니다. 주소 없이 호출한 목록은 필터를 내부에만 보관합니다. 삭제 후 페이지는 빈 주소가 아니라 `{ tab: search.tab, filters: search.filters }`로 돌아가며, 보기 사이의 다른 이동에서도 둘 다 유지됩니다.

목록이 주소에서 읽는 것. 목록 파일은 끝부분에서 자신의 주소를 한 번 선언합니다. 대상은 컨트롤을 그리는 필터 집합입니다(`<Entity>DrawnFilters`. 화면이 줄이기 전까지는 contract의 필터 전체이며, 컨트롤과 주소를 모두 이 상수 하나로 만들므로 상수를 줄이면 둘 다 줄어듭니다). 선언은 `<Entity>ListAddress`로 export하고 위젯 index에서도 export합니다. 페이지가 기간을 그리는 목록은 그 필드를 지정합니다(`timeRangeField`). 그러면 기간 스트립의 `<field>.between`과 필터 바의 두 경계 키를 주소에 담을 수 있습니다. 탭이나 페이지가 강제하는 그 밖의 요청은 목록을 첫 페이지로 되돌립니다(`scopeKey`).

| 멤버 | 용도 |
| --- | --- |
| `narrow(filters)` | 목록이 받아들이는 필터. 컨트롤이 확정하는 키만 남김 |
| `controls` | 각 컨트롤의 필드와 종류. 토글의 `true`와 숫자의 텍스트를 컨트롤이 확정하는 값으로 다시 읽는 데 쓰며 `filtersToRequestParams`에 전달 |
| `keys` | 컨트롤이 확정하는 필터 키 |
| `useAddressed(address, forced)` | hook. 목록의 hook이 `useCrudList`에 주는 `addressedFilters` 옵션 |

좁히기는 목록에 그 키를 확정하는 컨트롤이 있을 때만 키를 남깁니다. choice와 reference 필터는 `<field>.in`, 토글은 `<field>.equals`, 텍스트 필터는 선언한 연산자(필터 바가 아는 연산자를 선언하지 않으면 contains와 equals), 숫자 필터는 equals와 두 경계, 기간은 `greaterThanOrEqualTo`와 `lessThanOrEqualTo`를 씁니다. 목록이 패싯을 제공하지 않는 reference 필터는 컨트롤을 그리지 않으므로 키가 제거됩니다(목록은 주소를 선언할 때 패싯이 있는 필드를 지정합니다). 그래서 오래됐거나 직접 입력한 키는 서버가 거부할 요청에 포함되지 않고, 선언된 키가 하나도 없는 주소는 목록을 기본값으로 엽니다. 이 규칙은 `console-core/src/entity/list-address.ts`의 `declareListAddress`, `narrowAddressedFilters`, `filterControlsOf`에 있으며, 연산자 목록은 필터 바가 그리는 것과 같은 목록이므로 둘이 달라질 수 없습니다.

목록으로 링크하는 화면은 키를 같은 선언으로 처리합니다. 그래서 건수와 그 건수가 여는 목록이 같은 필터 집합을 읽습니다.

```tsx
const filters = JobListAddress.narrow({ "status.in": ["FAILED"] });
const count = useListCount(useListJobs, filtersToRequestParams(filters, { controls: JobListAddress.controls }));
const href = { to: "/jobs", search: { filters } };
```

화면이 필터 바가 아닌 경로(누른 타일, 칩 행, 기간 스트립)로 쓴 키도 다른 키와 마찬가지로 주소에 기록됩니다. 목록은 그 키를 쓴 목록이 마운트되어 있는 동안 다시 읽으므로, 사용자가 다음에 필터를 바꿔도 키가 유지됩니다. 밖에서 들어온 키(링크, 직접 입력한 주소, 새로 고침)는 선언만으로 읽습니다. 목록에 컨트롤이 없는 필드에 대한 링크는 제거되고, 새로 고침 후 선언되지 않은 시각 필드에 대한 기간도 제거됩니다.

탭. 필드를 고정하는 탭은 요청을 목록의 `params`(페이지 blocks의 `listParams`)로 전달합니다. `params`가 `equals`로 고정한 필드에 대한 필터는 적용하지 않고 필터 바도 컨트롤을 그리지 않습니다. 모든 요청에서 고정 값이 우선하므로 컨트롤이 어떤 행도 바꾸지 못하기 때문입니다. 이 키는 사용자가 다음에 필터를 바꿔 주소를 다시 쓸 때까지 주소에 남고, 그 필드를 고정하지 않는 탭에서는 다시 적용됩니다. 고정된 요청은 목록 컨트롤러에 실리며(`withForced`), `RecordList`는 이를 보고 제외할 컨트롤을 정합니다. 탭의 집합을 뜻하는 타일은 탭이 고정하는 필드에 대한 필터가 아니라 `?tab=<key>`로 링크합니다. 탭을 옮겨도 주소의 필터는 유지됩니다.

## 행 동작

`RecordList`와 `RecordTree`는 `actions`를 행 안의 아이콘 묶음으로 그리고, 카드에도 같은 묶음으로 그립니다. 동작을 실행할 수 없는 행에서는 비활성 상태와 그 사유를 표시합니다. 프레임워크 유형에 글리프가 없는 동사는 kit이 이름과 고유 글리프를 제공합니다(`retry`, `reset`, `test`, `reprocess`, `enable`, `disable`, `suspend`, `reinstate`, `cancel`, `revoke`, `upload`, `grant`, `adjust`, `approve`, `reject`). 그래서 화면이 재시도에 `duplicate`를 빌려 쓰지 않습니다.

행의 상태에 따라 뒤바뀌는 동사는 동작 하나로 선언합니다. `type`과 `label`을 행의 함수로 지정하세요.

```ts
{
  type: (row) => (row.enabled ? "disable" : "enable"),
  label: (row) => (row.enabled ? t("connection.disable") : t("connection.enable")),
  onClick: (row) => setSwitching({ row, turnOn: !row.enabled }),
  disabled: (row) => blocked(row),
}
```

함수형 `type`은 kit 동사를 반환합니다. 프레임워크 유형의 글리프는 프레임워크의 것이어서 행에 따라 바뀔 수 없기 때문입니다. 활성화와 비활성화를 동작 두 개로 선언하고 하나를 항상 비활성으로 두는 방식은 쓰지 마세요. 레이블이 붙은 묶음(프레임워크 유형 하나를 공유하는 두 동작. 영역 계약이 거부함)은 행에 있는 가장 넓은 레이블에 맞춰 컬럼 폭을 정합니다.
